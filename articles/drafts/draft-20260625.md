## 一、什么是Vibe Coding？为什么你现在就该关注它？

"Vibe Coding"这个词是2025年Andrej Karpathy（前OpenAI/Tesla AI总监）提出来的。他说：

> "有一种新的编程方式，你完全沉浸在'感觉'里，把编程当作和AI对话——你描述你想要什么，AI写代码，你看结果，不满意就继续对话。忘了代码本身的存在。"

翻译成人话：**你不需要学编程语言，你只需要学会"描述你想要什么"。**

2026年，这个趋势已经不可逆了：
- 昨天的对比文章刚测过——Claude Fable 5和DeepSeek写代码的能力已经达到高级工程师水平
- Game Jam（游戏开发马拉松）里，纯AI编程作品越来越多
- 少数派刚发了一篇文章，作者用100% Vibe Coding完成了整个Game Jam

**你不需要成为程序员才能做软件。你只需要成为"会描述需求的人"。**

今天这篇教程，我就带你走完全流程。

## 三、正式开始：全程对话式开发

### 步骤1：先让AI出方案，别急着写代码（关键！）

不要上来就说"帮我做一个游戏"——AI会乱写，结果大概率没法用。

**正确做法：先定框架，再逐步细化。**

把下面这段提示词复制到AI对话框：

```
你要帮我做一个网页游戏。在写代码之前，先不要动手，回答我这几个问题：

1. 根据我的需求，你建议做成什么类型最合适？
2. 需要哪些技术？（只用HTML/CSS/JS，不要框架）
3. 核心玩法循环是什么？
4. 文件结构是怎样的？

我的需求：
- 一个在浏览器里玩的游戏
- 简单但有可玩性，最好有计分系统
- 画面不需要太复杂，但要有基本的美感
- 1-2个文件就能跑起来

请先回答这4个问题，不要急着写代码。
```

> ⚠️ **这里有一个坑：** AI的默认行为是"你要什么我给什么"，直接甩几百行代码。但代码多了容易有bug，你也不知道怎么改。**先让它输出方案，你确认后再动手——你才是掌控者，不是旁观者。**

AI会回复类似这样的方案：

```
建议做成：Canvas射击小游戏
技术：HTML + CSS + Canvas JS（单文件即可）
核心玩法：玩家控制底部飞船，射击上方敌人，每波难度递增
文件结构：index.html（包含所有代码）
```

**你看一遍方案，确认没问题，再回复"开始写代码"。**

---

### 步骤2：让AI生成第一版（5分钟）

```
好的，按你的方案开始写代码。要求：
1. 所有代码写在一个 index.html 文件里
2. 玩家用键盘方向键移动，空格键射击
3. 敌人从上方随机出现，被击中后消失并加分
4. 有一个分数显示在屏幕上方
5. 画面用深色背景+霓虹配色
6. 代码写完告诉我怎么运行
```

AI生成代码后——**直接打开HTML文件，在浏览器里看效果。**

Cursor里右键 index.html → Open in Browser。

### 步骤3：你试玩 → 发现不爽 → 对话改（核心循环）

第一版跑起来后，你会发现各种问题。这很正常——**Vibe Coding的核心就是：你当测试员，AI当程序员。**

以下是你会遇到的典型情况及对应"咒语"：

**问题1："敌人太慢，没挑战性"**
```
现在的敌人移动太慢了。帮我把敌人速度提高50%，同时每过10秒，所有敌人的速度再自动提升10%。
```

**问题2："没有音效，少了感觉"**
```
帮我加音效：射击、击中敌人、游戏结束都要有声音。不要用外部音频文件，用Web Audio API直接在代码里生成简单的音效（比如射击用短促的"biu"声，爆炸用低频"boom"）。
```

**问题3："画面有点简陋"**
```
画面太简陋了。帮我加：
- 背景加入缓慢移动的星星（模拟太空）
- 击中敌人时加爆炸粒子动画
- 字体换成好看的（Google Fonts引入）

不要一次全改，先改背景星星，我看效果。
```

**问题4："死了只能刷新重来，太蠢了"**
```
加一个游戏结束界面：显示最终分数 + "重新开始"按钮。按下按钮后重置所有状态，不需要刷新页面。
```

---

### 步骤4：Agent闭环——这才是Vibe Coding的真正秘诀

少数派那篇文章的核心洞察是：**"Agent和人一样离不开闭环。"**

什么叫闭环？

```
你提需求 → AI写代码 → 你试玩 → 发现不对 → 告诉AI怎么改 → AI再改 → 你再试
```

这个循环走3-5轮，你的游戏就从"能跑"变成"好玩"。

**我的真实迭代记录：**

| 轮次 | 我做了什么 | AI做了什么 | 耗时 |
|------|-----------|-----------|------|
| 1 | 描述需求 | 生成初版代码 | 5分钟 |
| 2 | 试玩，反馈"太简单" | 加难度递增 | 3分钟 |
| 3 | 要求加音效 | 用Web Audio API实现 | 3分钟 |
| 4 | 要求画面美化 | 加粒子特效+星空背景 | 5分钟 |
| 5 | 要求加Game Over界面 | 加重启功能+最高分记录 | 3分钟 |
| 6 | 手机试玩发现没法操作 | 加移动端触控按钮 | 5分钟 |

**6轮对话，约24分钟，游戏从概念变成可玩成品。而且手机上也能玩。**

### 🔧 迭代修改提示词
```
我想改一个地方：[现在什么样] → [想要什么样]

改完之后如果影响了其他功能请一并修复。
只改我说的这个地方，不要动其他代码。
```

### 🐛 修Bug提示词
```
出了个问题：[描述现象，最好截图]

帮我在代码里找到原因并修复。先告诉我问题出在哪，再动手改。
```

### 🎨 美化提示词
```
现在的视觉效果不够好。帮我做以下改进（按优先级排）：
1. [改进1]
2. [改进2]

不要一次全改，先做第1项给我看效果。
```

## 六、常见问题

**Q: AI写的代码有Bug怎么办？**
A: 把报错信息或异常现象描述给AI，它会自己找Bug。一次没修好就继续描述现象，继续迭代。

**Q: AI改来改去把之前好的功能改坏了？**
A: 这是Vibe Coding最常见的痛点。解法：
- Cursor/Claude Code都支持回退到之前的版本
- 每次改完确认没问题后，手动备份一个文件副本
- 提示词里加一句"只改我说的，不要动其他代码"

**Q: 我不会判断AI写的代码好不好？**
A: 不用判断代码质量——**你只需要判断运行结果好不好。** 游戏好不好玩、网页好不好看、功能正不正常。你当产品经理，AI当程序员。

**Q: 免费额度用完了要花钱吗？**
A: Cursor免费试用2周（$20/月之后），Claude Code有免费额度，DeepSeek更是白菜价。如果只是偶尔做小项目，免费完全够用。

**Q: 可以做商业项目吗？**
A: 可以。越来越多独立开发者用Vibe Coding做产品并赚钱。但建议最终版本找个懂技术的朋友帮你检查一下代码质量和安全性。
