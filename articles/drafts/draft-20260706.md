## 二、用法一：把整份PDF论文/报告扔进去，让它帮你读

**省时：每篇论文/报告省30-60分钟**

DeepSeek V4的上下文窗口是1M token，实际大约能一次处理70-80万中文字——相当于一本《三体》的长度。这意味着你可以把几十页的PDF直接上传，让它帮你完成精读。

### 提示词

```
我上传了一份[PDF/报告/论文]，请帮我做三级阅读：

第一级-快速扫读（1分钟内看完）：
1. 这份材料的核心结论是什么？（一句话）
2. 作者论证这个结论用了哪3个最关键的论据？
3. 这个结论可靠吗？（有没有明显的数据问题或逻辑漏洞）

第二级-深度精读：
4. 逐章/逐节概括核心内容（每节控制在3句话内）
5. 标注出我可能需要的具体数据（标章节位置）
6. 哪些观点是作者的原创贡献，哪些是复述已有研究？

第三级-批判阅读：
7. 这篇文章最大的弱点是什么？
8. 如果你要对这个研究做后续补充，你会从哪个角度切入？
9. 有哪些作者提到但没展开的线索，值得深挖？
```

### 实测案例

我上传了一篇28页的AI行业分析报告（中文PDF），DeepSeek在约20秒内读完全文，给出了三级分析。第一级只用了一句话就把60页的核心说清楚了；第三级指出了报告里两个"数据口径不一致"的地方——这是我后来翻回去验证才确认的。

### 这个用法适合谁

- 每周需要看大量报告的咨询/分析师
- 在写文献综述的学生和研究者
- 需要快速了解一个新领域的任何人

> ⚠️ **坑：** 如果PDF是扫描版（图片格式而非文字格式），DeepSeek需要先用OCR识别。大部分情况下自动处理，但排版复杂的扫描件可能识别出错。遇到这种情况，先把PDF转成文字版再上传。

## 三、用法二：把Excel表格直接丢进去做分析

**省时：每次数据分析省1-3小时**

上上周我写"AI+Excel数据分析"时测了三个AI读表格的能力。DeepSeek的一个独特优势：**直接上传Excel文件，不需要截图也不需要复制粘贴**。

### 具体操作

**Step 1：上传Excel → 一句话让它理解数据**
```
我上传了一份[说明数据来源和内容的Excel]。你先看一下数据结构和字段，告诉我你理解了什么。
```

**Step 2：让它做分析**
```
好的，帮我分析：
1. 核心指标概览（总销售额、均价、同比变化）
2. 按[地区/品类/时间]拆分对比
3. 有没有异常数据？（某个月突然暴涨或暴跌）
4. 和上个月比，最大的3个变化是什么？
5. 基于这些数据，给我3条可以明天就执行的建议
```

### 实测效果

同一份销售数据（12个月×4个区域×8个品类），用Excel手动做透视表+图表大约需要40分钟。DeepSeek上传后约15秒给出完整分析，包含具体数字和趋势判断。

### 注意事项

- 数据涉及商业机密时，建议先脱敏（替换真实数字为大致比例）
- Excel里有合并单元格的话，先拆开再上传，否则AI可能读错数据结构
- DeepSeek目前不支持直接生成图表，但可以给你"用什么图表、X轴Y轴用什么"的具体建议

## 四、用法三：联网搜索 + 实时验证信息

**省时：每次信息核实省15-30分钟**

DeepSeek V4有一个手动开启的联网搜索功能。很多人不知道这个功能的正确用法：**不是用它"找资料"，是用它"验证你已经有的信息是否过时"。**

### 两个真实使用场景

**场景1：写作前的信息核实**

写文章需要引用数据时，把草稿贴进去，让它逐条验证：

```
我写了一篇文章，里面引用了一些数据和事实。请帮我开启联网搜索，逐条核实以下信息是否准确、是否有时效性问题：

1. "ChatGPT月活用户已突破2亿" — 最新数据是多少？
2. "Claude Pro月费$20" — 定价最近有变化吗？
3. "国内大模型已超过200个" — 最新的统计数字是什么？

如果有任何一条信息已经过时或不准确，告诉我最新的数据并标注来源。
```

**场景2：竞品/行业动态监控**

```
请联网搜索最近一周关于[某公司/某产品]的新闻，帮我梳理：
1. 有没有新功能发布或版本更新？
2. 有没有定价/收费策略的变化？
3. 有没有引起讨论的用户反馈或争议？

按重要程度排序，先说最重要的。
```

### 和直接百度/Google的区别

AI做这件事的好处不是"搜得更全"——是**搜完帮你总结**。你不需要自己点开10个网页，读10篇文章，然后自己做笔记。AI直接给你结论+来源，你只需要验证来源是否可信。

## 五、用法四：1M上下文做"全量对比"

**省时：每次合同/方案对比省2-4小时**

1M上下文的一个杀手级应用：**把两份长文档同时上传，让AI逐条对比差异。**

### 提示词

```
我上传了两份文件：
- 文档A：[说明，如：旧版合作协议]
- 文档B：[说明，如：新版合作协议]

请帮我做逐条对比，输出表格：

| 条款类别 | 文档A | 文档B | 变化 | 需要关注吗？|
|---------|-------|-------|------|-----------|
| [类别] | [内容] | [内容] | [变了什么] | [⚠️是/✅否] |

重点标注：
1. 权利义务有变化的条款
2. 数字/金额/时间有调整的地方
3. 新增的条款
4. 删除的条款

最后给出：如果你是乙方，这份新合同对你最不利的3个变化是什么？
```

### 其他可以对比的

- 两份产品方案/竞标书 → 找出差异化
- 两个版本的用户协议/隐私政策 → 标注隐私风险变化
- 两个竞品的官网介绍 → 营销话术对比
- 两份简历 → 候选人对比（脱敏后）

### 为什么这个只能用DeepSeek做

ChatGPT和Claude也支持文件上传，但免费版有上下文长度限制。两份几十页的合同同时对比，只有免费且1M上下文的DeepSeek能"零成本"完成。

## 六、用法五：把代码库/长文档当"知识库"反复提问

**省时：每次技术/文档查询省10-20分钟**

这个用法充分利用了"对话历史+长上下文"的组合。

### 操作方式

**Step 1：把整个文档/所有资料一次性上传**

```
我接下来要跟你讨论[某项目/某系统/某政策]，相关文档我都上传了。请你先通读所有材料，建立完整理解。读完告诉我你get到了什么。
```

**Step 2：在同一个对话里反复提问**

```
基于你刚才读的材料，我想问：
- XX和YY之间的关系是什么？
- 如果要改ZZ，会影响哪些其他部分？
- 文档里有没有提到AA的限制条件？
```

因为DeepSeek在当前对话中记住了所有已上传的文件内容，你可以像跟一个"已经读完全部资料的同事"一样连续提问。

### 实测案例

我把一个开源项目的10个核心代码文件全部上传，然后在这个对话里连续问了十几个问题——"这个函数在哪被调用的""如果要加一个新功能，改动最小的地方是哪""这个模块为什么要这样设计"——每个问题都得到了基于实际代码的回答，不需要重新描述背景。

类似用法也适用于：政策文件库、产品文档库、培训材料库。

## 七、DeepSeek V4 使用避坑指南

**坑1：联网搜索不会自动开**
> 每次新对话，联网搜索默认关闭。需要手动点一下搜索按钮。很多人以为AI在联网搜，其实没有。

**坑2：1M上下文不等于"无限"**
> 虽然1M token很大，但如果你在一次对话里上传了大量文件+长时间聊天，可能会超出。页面顶部有使用量提示，注意看一下。

**坑3：上传文件后不要马上切换话题**
> 先让AI"确认收到并理解文件内容"，再开始提问。直接跳过这一步，有时AI会忽略文件内容。

**坑4：数学计算偶尔翻车**
> 复杂的数据计算（多层嵌套的财务公式、概率统计），别直接信。用Excel验算一遍。AI在"语言理解"上是顶级，在"精确计算"上不是。

**坑5：它的"风格"偏工程师**
> 在"ChatGPT vs DeepSeek vs 豆包"那篇对比里我写过——DeepSeek的"文字人格"是严谨的工程师。写出来的东西信息量大、结构好，但少了点"人味"。如果你需要口语化表达，用我上个月教的技巧：生成后用这句话润色——"把上面这段话改成口语版，像在跟朋友聊天，删掉所有书面语的词。"
