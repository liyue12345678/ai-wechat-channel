# 🛠️ [实测] Gander 9B实测：腾讯混元语音开源全双工，边聊边干活走到哪一步了

> 📂 合集：**🛠️ 工具实测** | 模板：tool-review.md
> 发布日期：2026-09-24（周四）
> 适用对象：嫌 5600 亿全模态部署不起、又想本地实时语音视频的人；做交互 Agent 的开发者

---

**周二写 LongCat-Flash-Omni 的时候，最劝退的一句是：FP8 也要 8×H20。评论区如果有人回"那全模态是不是跟个人无关了"，今天这篇就是回信。**

9 月 9 日前后，腾讯混元语音团队联合浙大、上交、港中文、南洋理工，放出 **Gander**：论文标题是 Omni Interaction Agent。它不跟 560B 比谁总参更大，它比的是另一件事——**你说话时它能被打断，后台任务还能继续跑。**

一句话结论：**这是给"边聊边办事"开的 9B 研究模型，不是给"打开网页就能用"开的消费产品。能下权重、能起本地服务；别指望它长得像 LongCat Chat。**

> ⚠️ 声明：基于 arXiv:2609.08977、Hugging Face `Gander-Omni/Gander` 模型卡、GitHub Omni-Interaction-Agent 整理，未在双卡机器上复现全双工服务。论文里的 9B、人评和对比分，以报告为准。

## 它是什么：小脑管嘴，大脑管事

论文作者单位写得很清楚： **1 Hunyuan Speech Team, Tencent**，以及浙大 / 上交 / 港中文 / 南大（NTU）。

Gander 自己发明了一套分工，论文叫 **Cerebellum–Brain**：

- **小脑（Cerebellum）：** 实时看、听、说，全双工。Thinker + Talker 流式架构，输入输出在 chunk 级拉平成一条 token 流。  
- **大脑（Brain）：** 长程推理和 Agent 任务，经工具调用和编排 runtime 跟小脑持续通信。你可以打断它说话；它也可以在任务还没完时先回你一句进度。

Hugging Face 上的发布名是 **Gander-Unit8**（这里的 8 指每个说话时间片最多 8 个文本 token，不是"8B 的另一个名字"）。论文评测表把模型写成 **Gander 9B**。底座：**openbmb/MiniCPM-o-4_5**。许可：**Apache-2.0**，商用还要顺带核对 MiniCPM-o 和 faster-whisper 等依赖的条款。

时间被切成 **1 秒** 一个因果单元：这一秒的音视频观察先到，Thinker 再决定听、说、打断还是派任务。Talker 出流式 S3 语音 token，约 **0.5 秒** 一块波形。输入 16 kHz，输出 24 kHz，BF16。

**和 LongCat Omni 的差别，用一句就够：美团开的是"大一统全模态基座"；Gander 开的是"实时交互 + 异步 Agent"的系统。**

## 上手门槛：有卡能试，没有网页版可混

**没有**类似 longcat.chat 的"打开就能免费全双工"。官方路径是研究栈：

1. 权重：https://huggingface.co/Gander-Omni/Gander （`thinker/` + `talker/`）  
2. 代码：https://github.com/Omni-Interaction-Gander/Omni-Interaction-Agent  
3. 论文与项目页：arXiv 2609.08977；项目页 Omni-Interaction-Gander.github.io  
4. 数据集：模型卡写 **Coming soon**

完整实时体验按模型卡：配 MiniCPM-o 4.5 路径，Thinker / Talker 成对加载，**Talker 建议丢在第二张 GPU**（`detached_talker_device: cuda:1`）。然后：

```bash
git clone https://github.com/Omni-Interaction-Gander/Omni-Interaction-Agent.git
cd Omni-Interaction-Agent
cp gander_runtime/configs/serve.example.yaml gander_runtime/configs/serve.local.yaml
# 改本地路径
./scripts/serve.sh gander_runtime/configs/serve.local.yaml
```

二次整理提到本地打开 `http://127.0.0.1:8000`，并以 faster-whisper-large-v3 辅助识别——**以仓库 README 当时版本为准**，依赖变了以 GitHub 为准。

训练侧模型卡也写了：Thinker 1 个 epoch、8407 step；Talker 2 个 epoch、3246 step。这不是你要复现的作业，只说明它不是"换个 chat 模板"的套壳。

> ⚠️ 坑：单卡笔记本"我也能全双工"，和官方双卡示例不是一回事。显存不够就不要硬上实时口播。

## 核心能力：三个值得认真看的点

### 点 1：产品形态是"聊天时任务不断"

论文开篇情景不是写诗，是：屏幕上出现报错 → 你让它查原因 → 它说"我去干" → 你中途改口"幻灯片第 4 页留着" → 后台任务还在。这和扣子里拖一条"跑完再说话"的工作流相反。

**昨天教程把会议录音变成待办，用的是会后批处理。Gander 想做的是会中：听着、看着、异步执行。** 想清楚你买的是哪一种时间轴。

### 点 2：9B 打的是交互，不是 OmniBench 军备

论文用内部人评和分项表说话，并写明不同轴的分数**不可横向加总**。我这里不二次抄一串无法在你环境复现的对比小数。对读者有用的官方态度是：在保持开源语音对话自然度的同时，全模态交互有竞争力；对噪声、多人、backchannel（嗯、啊、抢话）专门做了鲁棒性叙述。

底座 MiniCPM-o 4.5 已是流式多模态交互路线。Gander 的增量是 **小脑–大脑 + runtime 生命周期**，不是再堆 100B。

### 点 3：它明确写了 Limitations

模型卡：模糊音频、画面快速变化、长时依赖时，事实和感知会错。外部动作要验证。定位是 **research**：实时多模态助手、全双工、流式视频语言、交互 Agent。

**这种段落比榜单第一更值得信任。** 做成客服之前，先接人审。

## 惊喜 / 槽点

👍 做得好的：

- **系统一起开源：** 权重 + runtime + 论文，不是只丢 safetensors。  
- **许可 Apache-2.0，** 和 MiniCPM-o 血统对研究友好。  
- **1 秒时间片写进 spec，** 工程上可讨论、可改，不是黑盒 Demo。

👎 需要改进的：

- **不是消费品。** 没有美团那种免费 Chat 兜底。  
- **数据还 Coming soon。** 论文说模型和代码数据会放，卡上仍写即将。  
- **双卡实时** 对个人仍偏研究。别和"星火 4B 塞笔记本"混为一谈——那是端侧文本/轻量，这是全双工音视频。

## 适合谁

- **值得 clone：** 做实时语音助手、要打断、要边说边调工具的团队。  
- **值得读论文就算了：** 只想开会后出纪要——用昨天教程 + LongCat Chat 更短。  
- **值得等等数据：** 要复现训练、要改交互策略的人。  
- **硬件：** 按官方示例准备多卡；单卡先只加载 Thinker 做非实时实验。

**一句话总结：Gander 把 9B 用在"嘴不停、事不停"上，和 560B 的 LongCat Omni 不是替代关系。一个是能试用的大基座，一个是能本地研究的交互系统。你的卡和你的产品形态，决定你该碰哪一个。**
