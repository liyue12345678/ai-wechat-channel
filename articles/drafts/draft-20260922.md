---

**昨天把论文 PDF 丢给书生-S2，它认的是页上的图和公式。今天换一种喂法：不打字，直接说话、开摄像头，看模型能不能边听边看边回。**

你如果还把"多模态"理解成"能传一张图"，这篇会把你的分类洗掉。**能看图的模型很多；能低延迟做实时音视频交互、还把权重开源出来的，仍然很少。**

美团 LongCat 团队开源的 **LongCat-Flash-Omni**，官方定位就是这个：总参 **560B**、激活约 **27B** 的 MoE，把离线多模态理解和实时音视频交互塞进同一套框架。服务端还有升级版 **LongCat-Flash-Omni-2603**，可以在 LongCat Chat 免费聊。

一句话结论：**普通人去网页/App 用语音就够了；想自己部署，先准备好至少一整机 8×H20（FP8）——这不是笔记本玩具。**

## 它是什么：不是又一个"能看图的聊天模型"

LongCat-Flash 家族先开了 Chat 和 Thinking。Omni 这一支，官方叙事很硬：在 **Shortcut-Connected MoE（含零计算专家）** 骨干上，加上轻量多模态感知和语音重建模块。微信公众号《LongCat-Flash-Omni 正式发布并开源》里写过一组很具体的工程数字：视觉编码器、音频编解码器都是轻量组件，参数量约 **6 亿**；上下文窗口 **128K**；宣称支持超 **8 分钟** 音视频交互。

端到端路径可以记成人话：

**看/听 → LLM 直接出文本和语音 token → 轻量解码器还原波形。** 不是"先 ASR 成字，再丢给聊天模型，再 TTS"那种拼装流水线。

和昨天的书生-S2 差在场景：S2 冲科学文献页；Omni 冲的是**实时交互**。参数量一个 35B/397B 预览，一个 560B 只激活 27B——都在讲"别只看总参"，但服务的人完全不同。

许可：**MIT**（模型卡写明）。权重：`meituan-longcat/LongCat-Flash-Omni`，另有 FP8 量化仓。

## 上手门槛：网页很低，自托管极高

**路径 A：别部署，直接用。**

1. 网页：模型卡写的是 https://longcat.ai ，并注明 **网页版当前主要支持音频交互**，完整能力后续补。  
2. 聊天产品：LongCat 更新日志写明，升级版 **LongCat-Flash-Omni-2603** 可在 https://longcat.chat/ **免费对话**，API 调用时指定 `model=LongCat-Flash-Omni-2603`。  
3. 官方还提供 Android / iOS App（模型卡"APP"一节）。  
4. API：OpenAI 兼容端点 `https://api.longcat.chat/openai`，另有 Anthropic 格式。先注册、创建 Key。

2603 相对开源 Omni 的官方卖点（更新日志原文要点）：对话更拟人；视/听/文准确率提升；支持**原生语音 Function Call**，宣称实时交互几乎零延迟。这是产品迭代说明，不是你我测过的延迟数字。

> 价格别混：API 按量付费文档当前写明支持的是 **LongCat-2.0**（限时价约输入 ¥2 / 百万 Token、输出 ¥8 / 百万 Token）。**Omni-2603 的按量单价我在公开价目表里没看到单独一行，不要按 2.0 的价去估算语音账单。** Chat 免费对话是另一条产品线。

**路径 B：自托管。** 模型卡写死了门槛：

| 精度 | 官方最低示例 |
|------|----------------|
| FP8 | 至少 1 节点，例如 **8×H20-141G** |
| BF16 | 至少 2 节点，例如 **16×H800-80G** |

环境：Python ≥ 3.10、PyTorch ≥ 2.8、CUDA ≥ 12.9。推理走他们改过的 SGLang 分支（`longcat_omni_v0.5.3.post3`），官方 SGLang 当时还不原生支持。单机 demo 是 `--tp-size 8 --ep-size 8`。

**如果你没有这一档卡，讨论"本地跑 Omni"没有意义。去 Chat。**

## 核心能力：三个值得认真看的点

### 点 1：它打的是"全模态一张网"，不是插件拼接

官方 OmniBench **61.38**，表上高于 Qwen3-Omni Instruct 的 58.41、Qwen2.5-Omni 的 48.16，低于 Gemini-2.5-Pro（ThinkingBudget128）的 66.80。DailyOmni **82.38**，表上高于 Gemini-2.5-Pro 的 80.61。

这些是官方对照表，评测设定以报告为准。对你有用的信息不是小数点，是：**他们愿意把 Omni 和 Gemini、Qwen-Omni 放同一张表里打。** 产品自信通常长这样。

### 点 2：文本没有因为"能说话"而崩掉

Instruct 版 MMLU **90.30**，和自家文本 LongCat-Flash 的 89.71 几乎持平；CEval **91.68**。LiveCodeBench pass@1 **52.64**，略高于文本 Flash 的 48.02。

这说明训练策略（课程式、从简单到复杂的模态序列）至少在官方数字上做到了那句承诺：**全模态，但单模态不崩。** 很多早期 Omni 的翻车点正好相反——会说话了，数学和代码先死。

### 点 3：语音 Function Call 才是 2603 的产品钩子

开源权重解决的是"研究/自建实时音视频"。2603 额外强调：**音频指令直接解析成工具调用。** 这和周四 NeoHorse、周五那篇"Agent 烧进模型"是同一条产业线——工具调用从文本 JSON，长进语音通道里。

我没在生产环境用语音调过他们的 Function Call。**能确定的是：官方把这件事写成了升级理由。** 你试用时，用一句能验证的指令（"查一下北京今天天气并读出来"）比空吹延迟有用。

## 惊喜 / 槽点

👍 做得好的：

- **入口分层清楚：** Chat 免费、App、开源权重、API，各走各的，没假装人人都能 8 卡部署。  
- **许可友好：** MIT，比一堆"研究专用"条款好谈。  
- **网页先音频：** 模型卡承认网页还不全，比假装"全模态 App 已完美"诚实。

👎 需要改进的：

- **网页能力不完整。** 视频实时交互别默认打开就能用。  
- **Omni API 价目不透明。** 2.0 有价，Omni 调用文档有、公开单价我没对齐。  
- **560B 开源对个人是观赏级。** 和书生 397B 同一类：下载按钮在，电费和卡不在你这。

## 适合谁

- **值得立刻试：** 想体验中文实时语音、少打字的人。走 longcat.chat / longcat.ai / App。  
- **值得盯仓库：** 有多卡集群、要做实时音视频助手的团队。MIT 权重 + demo 脚本。  
- **暂时不用硬上：** 只有一张消费级卡、只想本地跑——明天教程用的是 Chat 入口；周四写的 Gander 才是 9B 档本地故事。  
- **别用它干的事：** 科研读论文请回昨天的书生-S2；写长文用文本模型更稳。

**一句话总结：LongCat-Flash-Omni 把"实时全模态"从闭源演示，变成了可下载的 560B 开源件 + 可免费试用的 Chat。你要的如果是体验，打开网页；你要的如果是自己的延迟和数据，先数清楚有几张 H20。**
